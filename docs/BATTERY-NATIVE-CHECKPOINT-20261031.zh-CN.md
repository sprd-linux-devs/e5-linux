# 电量基准异常：时间交接与充满校正（2026-10-31）

## 已确认的缺口

本次继续调查同一台畅行60，而不是依据“更新后出现”回滚无关修改。
前一轮已确认保留UI为25.4%、normal为94.6%，因此显示会在充电中追赶错误高基准。
原始偏差最早产生时刻没有完整日志，不能把后续发现冒充那次写入的直接捕获。

### 1. 运行时长被误认为关机静置时长

本机原厂 `vendor/bin/charged` SHA-256：
`3458e12a8a19bc9ff4a422364d39bfdfd439be8b30bbd878ac27a7aa8e2b25a3`。
原厂版本为P720S20 `20240919.212928`。它与已留存P720S11原厂charged逐字节一致。

反汇编证据：

- `0x128c`调用 `time(NULL)`，`0x1298`定位miscdata的10500字节偏移；
  `0x1300–0x1310`以1字节×8写入64位时间。
- `0x1260–0x1268`的usleep参数为15000000，即循环每15秒保存，而非仅在关机时保存。
- 周围记录为magic、64位RTC、charge_cycle、BASP、两份异或编码的容量。
  容量密钥为 `0x20160726` 和 `0x15211517`。

LK读取这个“最后活跃时间”并生成 `charge.shutdown_rtc_time`，然后在开机时
把磁盘字段重置为当前时间。参考OpenHarmony所附展锐LK实现的
`sprdbat_format_cmdline`及同机磁盘/bootargs对照确认这一交接。
仅有“开机时LK重置”而没有charged心跳，运行半小时后重启就可能被判为关机半小时。
这会错误满足FGU至少900秒的静置门控。

本机OpenWrt此前没有对应心跳。#37启动仍得到早先时间，进入校准后才由新加的
300mV检查拒绝4.329996V的过期POCV。**检查陈旧POCV是必要补丁，但没有补齐
时间交接就仍有错误的校准机会，不能只做上一轮检查。**

### 2. 畅行60满充恢复没有接原厂SQC端点

本机原厂 `sprd-charger-manager.ko` SHA-256：
`89ff8ac7f8d4bb94986ef7938851b33b05a836e6ee6bf1af1a43cdbc8cb01518`。
由原始vendor_boot B取出，与已留存FGU/充电器模块交叉确认同一固件。

原厂 `cm_batt_works` 内联路径：

- `0x5084–0x5098`读取SQC状态并要求FULL=4；
- `0x511c–0x5164`读取电池电压并检查本机满电电压门槛；
- `0x517c–0x5190`通过FGU CALIBRATE写入1000，建立真实满电端点。

实际配置 `sqc_charger.conf` 的正常topoff电流为300mA；此前供体CM仍根据另一套
电流路径判断，没有完整消费本机SQC/硬件终止端点。源码差异已确认，当前未抓到
真实充满瞬间，所以不能声称实机已复现终止先后差异或完成满充恢复。

## 修复

- 公共电池服务加入原厂15秒时间心跳，复用原有ucode/uloop进程。
  这项定时工作只维护RTC交接，不轮询SOC、不产生额外电池电压采样。
- 写入前检查实际块设备、28字节记录、magic，以及本次LK提供的cycle、BASP、
  两份异或容量。不是凭机型名或看到magic就写固定位置。不匹配时不启用定时写入，
  原低电量守护保持运行。适用于通过相同原厂ABI核验的eMMC/UFS机型。
- 只更新10500处8字节时间，flush并回读；不写cycle、BASP、学习容量、SOC或NV。
  使用FGU同一个RTC时钟，避免OpenWrt墙钟与RTC不同步；原厂time(NULL)在正常
  Android中与RTC对应。未改系统时间或硬件RTC。stdio flush/close的语义与原厂一致，
  不能把缓存回读声称为突然断电后的持久性验收。
- 服务正常退出时最后保存一次；I/O故障记录原因并在下周期重试，不退出原低电量守护。
- 原厂SQC充满端点整理为公共、**显式选择**的内核准备策略，仅远航41S和畅行60
  接入。其他机型的充电芯片和满充策略不被替换。旧41S缓存迁移而不叠加新旧实现。
- 畅行60STATUS同时尊重软件停充，避免关闭充电后仍把遗留硬件状态报告为FULL。
  不根据显示100%、较高端电压或超时猜测“已经充满”。

## 实机结果

已热部署 #38 内核及235个完整匹配模块。磁盘摘要、实际加载的FGU/CM/充电器/
电池信息模块GNU build-id均核对通过，Android B摘要未变；未写GPT和原机NV。

这次正常重启日志为：

```
[5.617450] Boot calib: shutdown time = 18 not meet
[5.626653] SOC restore: ui=1000 normal=1000 first=0 recovered=0
```

短重启正确识别为18秒，不再把长期运行当900秒以上静置。重复回读证明心跳每15秒
更新；比较同一4KiB区域，除RTC的8字节外其他字节均未变。
真实执行过充电器停充/回读/恢复，Not charging及使能值正确，NCM/SSH保持连接。
这是BQ充电控制接口，不是FGU的SOC校准操作。

WAN、热点、HTTP管理页恢复，屏幕进程运行，未出现新BTF/符号不匹配、内核崩溃
或EXT4错误。设备临时模块副本已清理；电脑保留两次boot/模块备份及回执。
