# 电量计、充电器与 USB 的启动依赖恢复

## 范围与依据

针对“无电池百分比、不充电、USB 控制器缺失”的反馈，修复 Linux 移植代码中
可确认的依赖探测缺口。未取得故障机日志，不能认定反馈已经复现，也不能认定
其硬件换料。没有开放未知芯片或跨机型寄存器兼容。

原厂依据保持各设备已有采集记录：远航 41S/P720S11 为
`20240508.225723`，原厂内核 `5.4.254-android12-9-gd0931382de8e`；
畅行 60/P720S20 为 `20240919.212928`，原厂内核
`5.4.254-android12-9-g619997ff2210`。原厂充电芯片、地址、ID 和寄存器行为
仍分别使用 `devices/yuanhang41s/` 与 `devices/changxing60/` 的证据和适配。
本次修改的是 Linux 驱动依赖未就绪时的错误传递，不调整原厂充电策略。

## 确认的缺陷与修复

- FGU 主探测及 UMP96xx 硬件层在父 PMIC regmap 暂未发布时返回 `-ENODEV`。
  改用公共辅助函数，父设备存在但 regmap 未就绪时返回 `-EPROBE_DEFER`。
- BQ2560x、AW32257 在已描述的 syscon 平台设备或 PMIC regmap 未就绪时返回
  普通失败。现在同样延迟探测，并释放 `of_find_device_by_node()` 获得的平台
  设备引用，避免每次重试积累引用。设备树节点引用仍由调用端释放一次。
- FGU 将电池检测 GPIO、电源注册失败统一改为 `-ENXIO`，吞掉供应者未就绪
  错误；USB PHY 失败则全部改为延迟探测，包括真正缺失/无效的配置。
  现在保留这些接口原始错误码，只有实际的 `-EPROBE_DEFER` 才由内核重试。
- 远航 41S 早期模块列表补齐电池信息、CM、FGU、充电器；生成列表时复用已有
  模块依赖解析器，校验 ABI、补齐符号依赖并去重。畅行 60 原有早期电源链保留。

真正缺失的父设备、缺失/禁用的 PMIC 节点、芯片 ID 不符、I²C 故障仍明确报错。
没有固定 sleep、用户态循环重载、关闭 fw_devlink、虚拟电源或额外常驻服务。
没有修改 CPU/基带时序、NV、电流/电压编码、JEITA、满电校准、USB 角色和
主机＋外部供电策略。

## 公共接入

`devices/common/power-probe.py` 在 E5、T551M、M8 的底层准备入口末尾应用。
T512N、LYM10K、K1、远航 41S、畅行 60 通过对应父适配入口继承；板级充电
适配保持独立。测试也纳入通用本机构建器和 K1/远航 41S 原生构建器。

## 离线验证

`devices/common/test_power_probe.py --kernel <prepared-tree>` 在小型临时源文件
夹具中应用真实补丁，再编译执行实际 C 辅助函数及实际驱动错误分支：

- syscon 尚未注册 → 已注册但 regmap 未就绪 → 就绪，探测最终恢复；
- 一万次延迟探测后平台设备引用平衡，设备树节点每次仅释放一次；
- FGU GPIO/PHY/电源注册的延迟、缺失、无效、I/O、内存和忙错误逐一保留；
- 缺失父设备、缺失/禁用节点仍是永久错误；
- 原充电芯片/地址检查及电流、电压寄存器函数保持不变；
- 重复准备幂等，未知源码在写入前拒绝；再次执行原有 SOC 补丁栈不会覆盖修复；
- 8 个现有机型源码形态通过；远航 41S/畅行 60 机型及充电测试、SOC 恢复、
  充放电周期工作函数、容量映射和硬件满电端点回归通过。
- 远航 41S、M8、畅行 60 的 DWC3 主机/外部供电回归通过；41S 不适用的
  legacy CC 路径按机型跳过，该路径在另两款上通过。测试夹具补齐畅行 60
  延迟获取 boost 的模拟，覆盖未就绪后恢复、永久失败与设备模式无需 boost。
- E5、T512N 的 MUSB 角色/外部供电回归通过；没有改动 USB 策略实现。

使用既有 UMS9620 对象目录及生成头文件，额外对修改后的 FGU core、UMP96xx
硬件层、BQ2560x、AW32257 四个 C 文件进行了 ARM64 编译验证；只产生临时
对象夹具，不覆盖已交付的 Image/模块或历史发布包。

上述验证不等于故障批次实机验收。此次没有刷机、写硬件、更新安装包或修改
已有备份。将来交付须正常重编对应内核及完整模块，再生成含新模块的启动镜像。
