# 基带充电冷启动：不绑定原厂固件文件哈希

## 已确认的问题

旧 `e5-modem-coldboot` 用 5 个完整哈希选择固定补丁地址。
固件版本众多，文件中与加载逻辑无关的字节变化也会被拒绝。
现已删除生产代码中的 `PROFILES`、哈希判断和固定补丁偏移表。

外层条件保持：只有 charger、`modem=shutdown`、NR SBUF 未就绪时
生成 RAM 私有副本。正常开机、CP 已在线均直接使用原厂加载器。
不操作 AT、NV、IMEI、启动槽或固件分区，不新增固定等待／重拨。

## 动态识别

`openwrt/src/modem-loader-patch.c` 与 MU300 的同名辅助程序共用已核实
指令识别实现，支持 ELF64 AArch64 与 ELF32 ARM/Thumb。
按 PT_LOAD 映射转换地址，检查程序头边界、PM 谓词和 cmdline 引用，
完整验证 `modem=shutdown` 与 PM 已启动结果的合并门控。

ARM64 支持 SP 相对的 LDR/LDRB、FP 相对的 LDUR/LDURB，以及受约束的
寄存器、栈偏移和 NOP 变化。Thumb 额外通过动态段、ARM PLT/GOT 和
R_ARM_JUMP_SLOT 解析，确认 9 字节比较确实调用 `memcmp`。

加载协议必须有三个不同上下文的停止／启动配对，控制函数一致，
分别受 PM bit0、CH bit5、NR mask 0x0a 控制。只在唯一匹配时把 PM
谓词结果置零，并将初次加载 mask 从 63 改为 34，保留已经运行的 PM。
逐字节回读整份 RAM 副本，只有成功才原子发布；失败保留已有副本。

因此不再根据固件版本、整文件哈希或固定代码地址决定是否加载。
尚未核实的另一套指令 ABI 仍需补充识别规则，不能取消边界校验盲写。
SHA-256 仍用于源码构建收据和传输／文件完整性；它们不属于固件白名单。

公共 CPU 调压后端也去掉整分区／定长 SML 的哈希捷径，两个槽分别执行
本机 `sml-voltage-check`。能力缓存升为 v10，旧的哈希放行缓存不再复用。
MU300 通用 CPU adapter 同样统一算法识别；U30 Pro 原生双域 adapter
原本已经走算法识别，不套用 E5 三域或 MU300 加载器。

## 构建和多机型接入

- `devices/common/build-modem-loader.py` 使用现有编译器构建一个静态
  ARM64 程序，能处理两种原厂 ELF 架构；缓存仅在 `out/modem-loader/`。
- 所有机型的公共 `devices/modem-recovery.py` stage 安装它；E5、T551M、
  M8、T512N、41S、K1、LYM10K、Y60、畅行60不各写一套偏移。
- OpenWrt 公共构建及 Debian configure 路径均安装辅助程序。
  CI 校验辅助程序与当前源码的构建收据，避免新脚本配旧二进制。
- 不修改内核，无需因本次用户态修复重编 Image／模块。

## 验证边界

本地原厂样本核查：畅行60／K1 同 ABI、T512N、远航41S三种不同
ARM64 文件，以及 LYM10K 的 ARM32/Thumb 文件，定位与原人工核实
地址一致。历史哈希和偏移仅作为测试结果基准，不进入生产选择逻辑。

合成 ELF 回归覆盖地址重定位、不同寄存器／栈布局、版本字节变化、
两种架构门控逐条破坏、错误位掩码、错误 memcmp 绑定、模糊候选、
非法 ELF 和源／目标保护。外层测试覆盖正常启动、已在线 CP、失败／
超时不发布残缺副本。合成变体不是其他固件版本的硬件验收。
