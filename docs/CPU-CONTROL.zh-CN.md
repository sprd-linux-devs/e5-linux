# CPU 调频、电压与温控设置

网页入口：**蜂窝 → CPU 设置**（`/cgi-bin/luci/admin/modem/cpu`）。
屏幕入口：**设置 → 系统 → CPU 设置**。

两端通过同一个后端 `/usr/libexec/unisoc-modem/cpu-control` 操作，读取内核实际
支持的频率和调速器。页面不预设机型、CPU 核数、频率上限或传感器编号。

## 调频

按共享时钟的 CPU 频率域分别设置最低频率、最高频率和调速器。最低与最高选成
相同档位可请求固定频率，内核温控仍有权进一步降频。默认 `schedutil` 按负载
调节频率；`powersave` 请求最低频率，不代表所有负载下都最省电。

界面把用户设置的上下限与“当前有效范围”分开显示；温控暂时收紧上限时，
不会把临时降频值保存成用户配置。内核通过两个只读属性
`scaling_requested_min_freq` / `scaling_requested_max_freq` 提供原始请求值。

驱动通过原厂 SIP 固件接口读取档位和对应电压，并保留芯片分档、温度切换逻辑。
电压表显示当前固件实际使用的档位；新增的电压偏移通过固件原生启动接口生效。
仍不提供新增超频档位或逐频点单独改压。

## 电压偏移

每个供电域可以独立设置 **−50～+25 mV**，步进 **3.125 mV**。电压设置与
调频、温控的开机保存开关独立：选择偏移并保存后，**重启生效**。屏幕入口
在相应 CPU 域的“下次启动电压偏移”，网页位于“电压设置”的各供电域卡片中。
“查看频率与电压表”使用与 MU300 一致的主题弹窗，固定表头、限制高度并在内部滚动，
关闭后焦点回到入口，不撑长卡片。

界面分别显示当前偏移、下次启动偏移、PMIC 实际供电电压，以及当前固件电压表。
负载变化时电压与频率采样不是同时发生，瞬时读数可能对应相邻调频档位。
偏移由固件同时应用于 CPU 和匹配的 SRAM 表，保留原厂分档、温度表、调压时序
和电压下限处理。不是直接覆盖 PMIC 电压，也不是只改 Linux OPP 显示值。

电压配置为 `/etc/e5-cpu-voltage.json`。建议每次只调一档并验证自己的负载；
能保存的范围不代表每台芯片都能稳定运行。恢复默认会把下次启动偏移设为 0，
当前供电电压仍要重启后才能恢复。

启动保护：非零电压应用前，先同步写入 `/etc/e5-cpu-voltage-armed.json`；
正常关机的 K89 服务删除标记。如果崩溃、强制重启或异常断电留下标记，下次
会将电压配置移为 `.rejected.json` 并以原厂电压启动，避免反复应用不稳定设置。
手动停止 CPU 服务不会解除保护。此保护不能阻止首次不稳定导致的崩溃或数据损坏。
关机充电模式始终使用原厂电压，保存的偏移留到后续正常启动。

驱动作为模块由 S13 服务加载，在 S14 关机充电界面之前完成调频与温控初始化。
每次启动只允许初始化一次，没有运行中重置 DVFS、卸载或重新绑定的入口。
底层先检查已适配的 SoC 和配套驱动；SML 优先走已有白名单，未命中时匹配实际调压算法。
两槽允许不同版本，但各自必须能确认接口兼容。只读识别，不写 SML；识别不充分时维持原厂电压。
M8 的三簇为 CPU 0–3、4–6、7，使用独立核验的 UMS9620 SML，详情见
[M8 CPU 电压与温控](../devices/m8/cpu-controls.md)。PMIC 电源轨映射未核验时
不显示瞬时供电读数，固件频率/电压表仍可查看。

## 温控

只允许修改已经绑定 CPU 降频设备、且内核开放写入的被动温控阈值。阈值使用
1°C 步长，最低 40°C，最高不超过 100°C 且至少低于 hot/critical 保护阈值
10°C，各被动阈值按顺序至少相差 1°C。原厂回差、固件温度电压表和过热关机
阈值保留。未绑定 CPU 降频设备的传感器不会出现可编辑阈值。

当前原厂配置的被动温控起点为 70°C，温度检测从每秒一次切换到每 100 ms
一次；85°C 阈值绑定三个 CPU 降频设备，110°C 为不可在页面修改的过热关机
保护。调整第一项本身不直接触发降频，界面已区分两种用途。

## 保存与恢复

调频、温控默认修改只在本次启动期间生效。开启“开机应用调频与温控”后保存到 `/etc/e5-cpu.json`，
后续修改同步保存；关闭会删除开机配置，当前设置保持到重启。恢复默认会恢复
本次开机记录的默认策略与温控阈值，同时清除开机配置。

后端在写入前校验全部参数，按顺序修改频率上下限，并逐项回读；兼容异步
更新频率限制的内核，失败时回滚
已修改项目。开机配置与 CPU 拓扑不匹配或参数失效时拒绝应用，保存为
`/etc/e5-cpu.rejected.json` 并记录原因，避免每次启动反复尝试无效配置。

调频与温控初次验证内核：`6.18.54-t551m-cpu4-g020b970e351e-dirty`。
电压版本：`6.18.54-t551m-cpu5-g020b970e351e-dirty`。

| CPU 0–5 | 614.4–1690 MHz，共 11 档 | powersave 614.4 MHz；限频后 performance 1228.8 MHz |
| CPU 6 | 650–1703 MHz，共 10 档 | powersave 650 MHz；限频后 performance 1228.8 MHz |
| CPU 7 | 650–1703 MHz，共 10 档 | powersave 650 MHz；限频后 performance 1228.8 MHz |

- 临时将两个被动阈值设为 40°C / 41°C，三个降频设备均进入 state 4；恢复

- 降频期间保存设置，保留用户请求的频率上限，没有保存临时温控上限。
- 保存小核上限 1586 MHz、监测起点 69°C 后真实重启，两项均自动生效；

  实际听音、外设逐项插拔、TF 卡实际启动或长期续航对比；启动脚本与原版逐字节一致。

交付状态为原厂频率范围、`schedutil`、70°C / 85°C 被动阈值、110°C 关机
保护，开机调频配置关闭，电压偏移恢复为 0。

### 电压实测

在每个频率域的原厂最高频率固定采样五次，比较偏移 0 与 −3.125 mV：

| 频率域 | 固定频率 | PMIC 原始读数 | 降压后读数 |
| --- | --- | --- | --- |
| CPU 0–5 | 1690 MHz | 793.750 mV | 790.625 mV |
| CPU 6 | 1703 MHz | 843.750 mV | 840.625 mV |
| CPU 7 | 1703 MHz | 837.500 mV | 834.375 mV |

全部 31 个频率档位的固件表同步减少 3125 µV，最高档五次 PMIC 回读一致。
核对发现固件 domain 0/1/2 对应 PMIC 的 `vddcpu1/vddcpu2/vddcpu0`，不能按
数字后缀直接对应；后端按已核验 ABI 的供电路由取值。

真实 LuCI 测试保存 −6.25 mV，刷新后保留设置，当前电压仍显示 −3.125 mV；
屏幕真实 API 保存 +3.125 mV，同样只改变待生效配置。两端恢复默认均将下一次
偏移恢复到 0。这些测试不代表更大降压幅度、超频或长期续航已经验证。

恢复后真实重启，三个域全部 31 个固件电压值与原厂一致，最高档五次 PMIC
采样也全部恢复；正常关机确实清除了保护标记，没有误触发异常启动回退。
降压状态下调速器切换和被动温控实测通过，恢复阈值后解除降频。

### E5 原厂固件适配与实测

E5 内核 `6.18.54-e5-mobile1-g020b970e351e-dirty` 已包含同一调压驱动，
此前只因双槽 SML 的 SHA-256 未在已验证清单中，网页与屏幕显示不支持。
对照本机固件的 DVFS 初始化、参数解码及 CPU/SRAM 表更新路径后，确认使用
同一原生 ABI，新增精确固件校验，无需替换安全固件或重刷内核。
具体固件指纹和函数地址见 [驱动说明](../devices/t551m/cpufreq/README.md)。

真实重启应用三个域各 −3.125 mV：全部 31 个固件频率档位同步减少 3125 µV。
在原厂最高频率连续采样五次，PMIC 结果一致：

| 频率域 | 固定频率 | 原厂 PMIC 电压 | 降压后 PMIC 电压 |
| --- | --- | --- | --- |
| CPU 0–5 | 1690 MHz | 756.250 mV | 753.125 mV |
| CPU 6 | 1703 MHz | 806.250 mV | 803.125 mV |
| CPU 7 | 1703 MHz | 796.875 mV | 793.750 mV |

PMIC 的供电域映射仍为 domain 0/1/2 → vddcpu1/2/0；SRAM1/2 随表调整，
本次 SRAM0 回读保持 750 mV，并非所有 SRAM 实测值都等量下降。
恢复 0 偏移并再次真实重启后，31 个档位及最高频率下五次 PMIC 采样全部回到
原厂值，正常关机清除保护标记。交付仍为默认频率范围与 `schedutil`。
网页与屏幕共用同一后端；网页三个域的电压控件及主题电压表弹窗均通过实机检查。
基带 WAN、热点、USB 网络和屏幕服务正常，九个物理 NV 分区校验不变且仍只读。
默认启动系统与 TF 启动保留。此次只验证最小降压档，不代表更大幅度的长期稳定性。
