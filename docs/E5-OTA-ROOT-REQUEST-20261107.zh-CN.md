# E5 差异更新保留分区启动请求

参考 PR：<https://github.com/kanoqwq/e5-linux/pull/1>。

LYM-10K 报告中，LK 从启动头偏移 64 读取 v4 的命令行字段（实际偏移 44），
截掉前 20 字节。Android userdata 加密、根内没有 part-autoboot 时，安装器追加的
`etc/e5/boot-request` 是剩下的分区启动选择入口。

已在当前共享 OTA 源码上用合成 boot 离线复现：Binder 丢弃这个文件，且保留旧
未填充的启动头，因此给新 canonical boot 加填充也不能单独修复既有安装的 Diff。
这是公共元数据筛选缺口；目前明确的实机故障报告来自 LYM-10K，不能据此断言
其他机型一定发生或绝不会发生。此前 Pro 的存储脚本保留修复没有覆盖此文件。

修复分为两层：

- LYM-10K 新包采用 T512N 已有的 20 字节 LK 填充；其他机型的包参数不变。
- 公共 E5 OTA 保留当前机器已有的有效 `e5.root=part` 请求，连同原来的槽位信息
  绑定进新 ramdisk 和恢复 guard；没有该请求的机器不新增它。
- 一次性 `part_prepare`、多条／异常请求或链接条目在写入启动分区前拒绝，避免
  重放存储维护。带本机请求的错误 canonical 镜像也不会给无此请求的机器强加模式。
- 安装器离线更新保留包本来带有的 LK 填充；未填充包的更新参数与原来逐字节相同。
- 原始 boot 备份、Android 槽、诊断尾部、内核／模块选择和原来的撤销流程保留。
  不添加通用强制自启动标记，不强制把 TF 或镜像安装切成内置分区。

离线回归覆盖 A/B 双向槽位、已截断的命令行、原始恢复 guard、连续三次更新、
ramdisk 尺寸稳定、无启动请求的 E5/MU300 以及异常请求拒绝；完整事务与撤销
仍使用普通临时文件模拟分区。离线结果不替代各机型的实机重启／断电验收。
另与修复前安装器 `78cfdd3` 对照：不含启动请求的 E5、MU300 测试镜像，
A/B 两个方向的完整绑定输出均逐字节一致。

共享修改位于 installer 子模块的 OTA boot.py。旧工具已生成的补丁不会自动变化，
需要在正式交付时重编工具并重新生成补丁，更新对应子模块引用、版本锁和归档摘要。
共享源码修复提交为 `ab2f30c`，E5 的安装器输入锁与本轮正式打包同步更新。
