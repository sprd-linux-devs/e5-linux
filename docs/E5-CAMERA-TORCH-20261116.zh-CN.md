## 已完成：AW3641 手电筒

本机原厂 `modules.load` 选择 `flash_ic_aw3641.ko`；其 SHA256 为
`94d4451cc04d1c4086fb977fd5168b8fd8ea20c1f8e01d60ce68866b363b7683`。
有效节点是根下的 `flash-gpios`，compatible 为 `sprd,flash-aw3641`。
DT 中另一个 OCP8137 节点不代表这台机器实际装了 OCP8137，不驱动其 GPIO。

`devices/e5/port/torch/` 实现标准 LED class 驱动；GPIO 从实际 DT 取得，
不写死全局 GPIO 号。按原厂二进制核对的顺序：

- 点亮：MODE 拉低，再将 EN 拉高。
- 熄灭：EN 拉低，再将 MODE 拉低。
- 探测后默认熄灭，卸载、关闭系统时熄灭。

接口为 `/sys/class/leds/e5:white:torch/brightness`，支持 0（关）、1（开）。
只支持已验证的手电筒常亮模式；尚不支持相机同步闪光或高电流脉冲。
GPL 参考代码、原厂证据和许可证记录在同目录 `SOURCES.json`。

### 信息屏应用

E5 的组包路径安装 `devices/e5/infoscreen-torch/`。应用中央为手电筒图标，
点击切换，显示实际开关状态；退出页面不偷偷改变照明状态。
每次进入、页面恢复可见或屏幕唤醒时只读硬件状态，没有后台轮询。
POST 在后端根据当时实际亮度切换，随后回读确认。提交期间禁用重复操作；
请求失败后只读同步，不自动重试写入，以免超时后把已经点亮的灯再次关闭。
驱动缺失显示“手电筒驱动未就绪”，禁用开关并提供重新读取。

页面跟随信息屏的明暗主题、字体大小及壁纸，具有中文／英文／土耳其文。
其他机型不安装这个 E5 专属入口。
`test_torch_backend.uc` 执行实际 ucode 后端并替换硬件文件访问，
验证外部变更、固定路径、写入失败与回读失败；
`test_torch_browser.py` 使用真实 SDK／HTML／JS，覆盖重新进入、外部改灯、
连续点击、提交后响应丢失、驱动不可用及恢复、翻译、无轮询和 iframe 主题布局。
应用现已热部署，真实屏幕服务的 API 已验证；用户实际点按与视觉体验仍待确认。

### 完整包、普通更新与 diff

应用的唯一代码源放在 `/usr/share/e5-infoscreen/builtin-apps/torch`，
入口 `/usr/share/e5-infoscreen/www/plugins/torch` 是指向它的相对软链接。
代码不放在当作用户配置保留的 `/etc/e5-infoscreen/plugins` 中，避免后续更新
保留旧版代码、或者通过指向 `/etc` 的父软链接写入而被 diff 拒绝。
E5 的共享屏幕 staging 也调用 `torch-screen.py`，屏幕独立更新不会漏装。
驱动由本机内核的完整模块树交付，完整镜像带标准 modules.d 自动加载文件；
现有信息屏服务另调用只加载 E5 驱动的 `e5-torch-start`，保持已经点亮的状态。
因此即便保留了旧自动加载配置，升级后的启动流程仍能加载新交付的模块。

`test_torch_delivery.py` 使用真实 diff 生成器与事务引擎，在临时根中完成首次
diff 和第二次代码升级；执行普通镜像的实际配置迁移及应用链接逻辑。
验证模块、启动入口、页面和后端均能交付，旧应用不会遮盖新代码，
Wi-Fi 密码、壁纸及第三方应用保留，其他机型不出现 E5 手电筒入口。
同时执行实际屏幕启动函数，验证可选加载器失败不影响信息屏启动。
这是离线更新回归，未对实机执行 OTA；未改变更新完整性或配置保护策略。
