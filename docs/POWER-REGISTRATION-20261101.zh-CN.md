# 电池缺失与物联卡启动慢：源码检查及修复

## 证据边界

本轮收到畅行60/远航41S部分机器无电量、无充电状态，以及物联卡首次驻网
超过一分钟的反馈，没有故障机器的启动日志或原厂对照。下面是已确认的代码
缺口，不代表已经复现两类反馈，也不能认定全部故障批次已经修好。

原厂依据沿用各机型自己的备份：41S/P720S11 `20240508.225723`，畅行60/
P720S20 `20240919.212928`。不改变充电电流/电压、JEITA、USB角色、NV或电量校准。

## 电源公共路径

在已有 PMIC/GPIO/USB PHY 延迟探测修复上补齐以下缺口：

- FGU power_supply 尚未初始化时，get/set_property 把暂不可读报告成 ENODEV。
  改为 EAGAIN；充电管理首次读取启动容量、温度遇到此状态时返回 EPROBE_DEFER，
  让内核按供应者就绪事件重试，而非永久丢失 battery 对象。
- 两条充电管理失败出口补齐持有的 fuel_gauge 引用释放。
- UMP96xx FGU 只比较 DT compatible 列表第一项。改为标准 of_match_node，
  表尾补终止项；仅接受列表中明确包含的已支持硬件，不新增未知 PMIC 寄存器表。
- FGU 硬件层返回的所有错误原先都被改成 EPROBE_DEFER。现保留原错误码：
  真实供应者晚就绪继续延迟探测，未知硬件/无效配置不再伪装为等待依赖。

这些修复进入公共 power-probe 准备器，各机型通过既有准备入口继承。

## 41S 充电地址

`dumps/yuanhang41s-stock-20261020/reference/vendor_dlkm/lib/modules/sqc_bq2560x.ko`
SHA256 `ba6dde2ad1009c49ae81891ad59cdb0a354f9bb15c12371c37d357296127c310`：

- probe `0xe80–0xe9c` 在当前 I2C 地址读取 REG0B，提取 PN[6:3]/SGMPART[2]；
  PN=0 分支指向 `.rodata+0x3521` 的 `sgm41513`。
- `0xfe0–0x1004` 是读不到初始地址后的 `0x1a` 地址交接。
- Linux 旧适配在识别前无条件改到 0x1a，绕过了原厂对 DT 地址的识别。

改为先读 DT/当前地址，仅对 0x6b 的地址不应答错误 ENXIO/EREMOTEIO 尝试原厂
0x1a；已确认的 SGM41513 PN 才继续初始化。I/O/超时错误保留；未知芯片不写入，
失败时还原地址。已选择 0x1a 的延迟重试继续使用该地址。未把 SQC 的其他芯片
分支照搬进来，M8/K1/畅行60各自的地址和编码不变。

这证明旧代码有地址选择差异，不证明反馈机器实际使用哪种芯片/地址。

## 物联卡与首次驻网

确认公共 network-startup-defaults 漏列畅行60，以及实验机型 Y60，导致原始
`network.wan.init_epsbearer=default` 未迁移为已有的 keep 策略；此设置可能在
初始化后再次执行 EPS 参数更新及电源切换。已补齐名单及全部发布 profile 测试，
畅行60 RAM 测试根也使用 keep。

仍只在首次且值为原始 default 时迁移；已有迁移标记、custom/connection/keep/
空值及后续用户选择均保持。没有缩短注册超时、并行发送 AT、绕过启动回放、
关闭副卡或循环重置射频。

核对当前 ModemManager 1.24.0 Unisoc 插件和通用 3GPP 状态机：
LTE/5G 分组业务可独立完成注册，恢复入口不要求 IMS 或 CS 注册成功。
没有证据证明“没有 IMS”就是这次一分钟等待的原因。E5 等已完成迁移的机型
不会因本次名单补齐再改变设置；若仍慢，需要该机启动阶段及 AT 时序才能区分
SIM 读取、真实注册、漫游、PDP 激活，不能承诺所有物联卡秒出信号。

## 离线验证与交付

- 公共电源真实 C 回归：迟到供应者、未知 compatible、两种 compatible 排列、
  EAGAIN 与永久错误区分、引用平衡、重复准备及旧 SOC 补丁重放通过。
- 使用已有 41S 对象目录，对 FGU core、UMP96xx、CM、BQ、AW 五个文件完成
  ARM64 临时对象编译；不覆盖已有 Image/模块。原有未使用函数警告保留。
- M8/41S/K1 充电适配 7 项、畅行60充电 3 项、网络启动 18 项、畅行60网络
  1 项、注册恢复 15 项通过。包含实际识别 C 的全 256 个 ID、地址不应答回退、
  超时/错误/未知芯片、重复准备，以及两槽 LTE/NR 无 IMS 的恢复测试。
- 启动 SOC、周期容量更新、1003 个原厂容量映射输出、满电/回充/平滑回归通过。
