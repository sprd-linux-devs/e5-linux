# T551M 充电芯片批次适配

## 故障与原厂证据

已确认缺陷：旧 T551M 适配只接受 I²C 6-006b 的 REG0B=0x12，另一批
REG0B=0x11 被拒绝探测，导致依赖此充电器的电池／USB 功能不能完整初始化。
不能只放宽 ID 判断：两批芯片的充电电流编码不同。

本轮实际设备为 TYT_00CM_FIH，固件 551MCM08，Android 13，内核
5.15.123-android13-8-00033-g39606e3309fc-ab10974680，板号
RA96A_V1.0_20231201。原厂日志确认 REG0B=0x11；原厂系统显示电量和充电正常。
仅提取本机 DT 与模块分析，不改 NV、IMEI 或电池记忆。

## 按芯片选择电流编码

原厂 `set_current`（0x2d08）读取 REG0B 低两位选择 A5/A6，电流单位先从
µA 转为整数 mA。原厂 getter 在 `usb_get_property`（0x3c90）中。

| ID | 请求编码，mA | 解码，mA |
| --- | --- | --- |
| 0x11 | 上限 2875；小于 59 为 0；59–815 为 `(mA-59)/63+1`；其余为 `(2*mA-1610)/115+14` | 码 0 为 0；1–13 为 `code*63-4`；其余为 `(code-14)*115/2+805` |
| 0x12 | 上限 3047；不超过 1170 为 `mA/90`；其余为 `(mA-805)/57+14` | 0–13 为 `code*90`；其余为 `(code-14)*115/2+805` |

所有除法保留原厂整数向下取整。输入限流仍是 REG00 的
`100 mA + code*100 mA`，与电池端充电电流不是同一个值。
常温 DCP 请求仍沿用现有完整电池参数匹配后的 3 A 配置；0x11 实际电池端
上限是 2875 mA，不能通过套用另一芯片编码伪造更大电流。

REG04 的终止电压上限仍为 4.4 V。SDP/CDP、JEITA 温控、输入电压限流、
普通 OTG 的 REG01 升压控制、主机＋外部供电模式及退出流程保持原有实现。
只在 0x6b 且 ID 为已核实的 0x11/0x12 时接受芯片，不探测写入其他地址。

## 验证范围

`devices/t551m/test_charger.py` 编译生成驱动的实际函数，用模拟寄存器验证
两种编码的全段请求、全部 64 个解码值、其他控制位保持、输入限流、终止电压、
看门狗恢复及 I/O 失败。参考结果来自原厂 ARM 指令的定点除法，独立于适配公式。
`build-kernel.sh` 在编译前执行此测试及 `test_charge_profile.py`，防止只修实机
而遗漏后续构建。公共 USB 主机＋外部供电回归由正式内核构建入口继续执行。

离线模拟不代表充电功率或扩展坞实测通过；这两项需按实际部署后的结果另记。

## 本轮实机结果

部署后实际加载的充电模块 SHA-256 为
`61cb9729d957ceffb249020c24f43f009c04bfeb5aa2be2e3591b53c278b693d`。
内核确认 `T551M charger REG0B=0x11 at 0x6b`，45 个早期模块均加载成功。
电池与充电管理接口恢复，读到 97–98%、约 4.34–4.35 V、Charging/Good、
4.4 V 终止电压；电脑 SDP 输入限流 500 mA，REG02=0x88，正确读回 500 mA。
独立充电器接入后内核读回 DCP 输入限流 3000000 µA，REG00[4:0]=0x1d。
电池接近充满，本轮不以电流表功率证明低 SOC 的最大持续充电能力。

用户实测确认独立充电、自动 OTG、手动主机、带独立供电扩展坞的主机＋充电
均正常。对应日志确认普通主机 `external=0` 启用本机升压，退出关闭升压；
外部供电主机 `external=1` 不启用本机升压。接回电脑后策略为 auto、数据角色
device、NCM 为 480 Mbps，电池仍显示 Charging，蜂窝 WAN 已联网。

新批次变体仅在 T551M 的主准备入口调用。M8/K1/41S 使用的共享 A6
基础转换输出与修改前逐字节一致，各自的芯片判断、充电编码和电压配置不变。
收尾重编的充电模块 SHA-256 为
`cd0767fce3f0787e43576973aa70fa98dd221f0908ac52bdac7b501d6c61825c`；
其可执行 `.text` 与上述实机模块逐字节一致，SHA-256 为
`f2e3900459b69373c44286037cacd28efff19429837f868726c8fa6d01fe9e4b`。
本轮检查还发现 M8 旧回归中两项 41S 测试仍断言已被现行识别 helper 替代的
旧内联代码；本次未修改这些旧断言。M8 的四项当前基础／变体隔离测试和 41S
自己的两项充电回归通过，不将旧测试的失败记为本次硬件适配失败或全套通过。
