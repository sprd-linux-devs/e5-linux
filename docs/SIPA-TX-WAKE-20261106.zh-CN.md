# 公共 SIPA 授权与唤醒修复

`devices/common/sipa-rm-order.patch` 接在现有数据路径、重试和完成事件补丁后，
由公共 `sipa.py` 统一接入各机型 prepare。它适配本仓库现有驱动基线，
没有用 Pro 驱动替换当前实现。

- 防止已经到达的 GRANTED 被迟到的 `-EINPROGRESS` 重新标记为等待。
- 队列是否停止的检查与唤醒进入发送路径共用的锁，消除先略过唤醒、后停止的交错。
- SIPA USB 网卡停发前核对当前 RM 状态；分配失败和发送硬错误正确消费 skb，
  BUSY 重试保留原包。该部分是网卡数据路径，不改变 USB 角色和供电控制。

`devices/common/test_sipa_flow.py` 编译当前生产函数，七组测试覆盖提前、立即、
真正等待和失败授权，真实线程制造 Ethernet/USB 停发竞态，以及发送所有权。
该检查已接入现有 `test_sipa.py`，同时验证旧补丁迁移、重复应用、发送重试、
完成回收、CP 电源引用和不兼容源码拒绝。ASan/UBSan 离线回归通过。

本轮没有在 E5 机型实机复现，不把 Pro 现场当作本仓库硬件验收。

已通过登记的 E5 主机型源/对象路径重新编译 Image 和配套模块，内核构建及
公共驱动回归通过。其他机型通过同一 prepare 入口接入补丁；尚未逐机型重新
编译或打包，不能把公共接线通过写成所有机型产物已经更新。
