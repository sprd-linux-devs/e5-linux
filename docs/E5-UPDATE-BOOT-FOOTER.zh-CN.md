# 普通更新同步启动镜像尾部

2026-11-19：远航 41S 的网页差分检查报 `Invalid boot payload bounds`。

## 已确认的现场与原因

本机 Linux 在 A 槽、Android 在 B 槽。Linux boot 的 ramdisk 与 AVB 数据完整，
但分区末尾 footer 保存的 AVB 地址比实际位置早 4096 字节，落进压缩 ramdisk。
更新器按现有边界检查拒绝处理；新包中的启动镜像边界正常。

`tools/e5-update.py` 的普通 SSH 更新只上传启动镜像前 56 MiB，
`openwrt/device-flash-boot.sh` 只写入并核对这些字节，遗漏分区末尾的 64 字节。
按设备槽位绑定追加 ramdisk 后，AVB 位置可能跨页，旧 footer 因而与新正文不一致。
这条普通更新路径由 E5 九款共用；不是每次更新都会改变 AVB 地址。

## 修正与交付

宿主工具把启动镜像前缀和匹配的 64 字节 footer 一起作为受摘要保护的传输文件。
设备端先核对传输摘要、长度及 footer 标识，再根据当前内部存储分区容量分别写入
前缀与末尾。两部分回读通过后才设置 Linux 下次启动。中间的持久日志区、Android
槽和其他分区均不在写入范围内；写入或回读失败不会发布系统更新请求或触发重启。

这不放宽网页差分的现有 boot 校验。普通更新辅助程序和脚本是包内宿主文件，
可通过既有 `refresh-installers` 路径交付；该路径核对 boot、系统镜像和 ext4
工具载荷字节保持不变，不需要重编内核或重新制作根文件系统。

## 验证

- 实际设备原镜像已在电脑备份并核对 SHA256。获授权后仅更正 footer，整份镜像
  核对确认其他字节未变；未重启，重新检查原差分包通过。未由本次修复自动刷入差分。
- 临时普通文件执行实际写入脚本，覆盖 eMMC/UFS、两个 Android/Linux 槽位方向、
  日志保留、缺失/截短/无效 footer，以及尾部回读失败时禁止设置下次启动和重启。
- 连同槽位绑定、分区更新参数、容量传递共 25 项离线测试通过。
- 快速组包回归通过实际 ZIP 刷新器验证脚本替换、清单摘要和固件载荷不变。

离线测试的全局 `sync` 使用局部桩，避免触碰测试外的宿主挂载；实际 `dd`、
每文件 fsync、存储解析和回读校验仍执行。不把这些离线结果表述为九款实机验收。
