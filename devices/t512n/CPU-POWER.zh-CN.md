## 调压接口

以下地址以文件偏移 `0x200` 对应加载地址 `0xb0000000` 计算：

- SIP 分发使用 `0xb0014c60` 的 13 项跳转表。`0x8200060b`
  对应 `0xb000debc`，调用 `DVFS_INIT` 的 `0xb00075c0`。
- 初始化保存传入 flag，在 `0xb0007788` 恢复该值，
  `0xb000778c` 调用 `0xb0006578` 解码。
- 解码器取 bits 8..15、16..23、24..31；每字节 bit7 为负号，低七位为 mV，
  幅度不超过 100，保存到三个域的状态 `0xb0029328 + {0x1c,0x4c,0x7c}`。
  低字节原有调试标志保留。
- `0xb0004410..0xb000447b` 与已核验 T551M 的
  `0xb0004090..0xb00040fb` **逐字节相同**：
  以 `(mV*1000 + 3124)/3125` 计算 selector 步数，根据符号增减表项。
- 三个域的 CPU/SRAM 表均成对调整：调用点分别为
  `0xb0005958/0xb0005964`、`0xb0005520/0xb000552c`、
  `0xb00050e8/0xb00050f4`。调用前检查温度表缓存，避免对同一表重复加偏移。

因此本机可复用现有 CPUFreq 一次性初始化接口。公共 CPU 后端新增本机完整
固件哈希，能力缓存更新为 v4，避免旧的“不支持”缓存阻止热更新后启用。
仍要求 UMS9621 且两槽固件相同；未知固件或混合槽位不开放调压。

网页和屏幕共用该后端，三簇均支持保存下一次启动的电压偏移，范围
−50 至 +25 mV，步进 3.125 mV；默认 0。模块不允许重载或重复初始化，
异常关机后恢复原厂电压的机制保留。不直接修改 PMIC、SML、NV 或 DTBO。
此范围是接口范围，不代表所有取值均经过本机稳定性测试。

## 温控

本机 DT 的 `soc-thmzone`：70°C 提高监测频率，85°C 进入降频，
110°C 为 critical；正常/被动监测分别为 1000/100 ms。
使用本机虚拟传感器列表和三个 CPUFreq cooling 设备，未覆盖成其他型号阈值。
网页与屏幕均可调整被动阈值，critical 不对外开放修改。

实机临时设为 40/41°C 后，CPU cooling 确实进入限制状态；恢复 70/85°C 后
cooling 回到 0，用户频率上下限及 schedutil 均恢复。没有保存测试用温控配置。

## 省电边界

- 内核已经启用 NO_HZ_IDLE、高精度定时器、PSCI cpuidle 和 menu。
  实机 `core-sleep-lit`、`cluster-pd` 的进入次数和驻留时间均非零；
  这证明 CPU 空闲路径工作，不是整机深睡或续航增益的测量结果。
- 三簇使用 schedutil、原厂频率范围；没有默认降频、降压或降低业务轮询率。
- 公共 watchdog/DPU/GPU/相机电源域修复已经由 T512N 的内核准备入口继承。
  实机相机 MM 域及未使用子域为 off；显示点亮时 DPU/DSI active 属正常状态。
- 保留 runtime PM、已有 USB/充电/音频/基带行为，不禁用 eMMC 休眠。
  不为省电增加另一个常驻轮询器或强制整机挂起。
- 当前内核仍含 bring-up 的 `clk_ignore_unused`、`pd_ignore_unused`、
  `regulator_ignore_unused`。它们并未关闭运行时 PM 或 CPU idle，
  但尚未验证移除后的全部资源归属。此前全局 `clk_summary` 曾触发寄存器访问
  SError，不能盲目开启全树访问/清理，也不能将本轮写成所有省电收尾已完成。

## 验证记录

- 公共 CPU 后端 22 项离线回归通过，包含本机哈希仅适用于 UMS9621，
  以及 v3 负缓存刷新；离线通过不替代硬件效果。
- 本机三簇分别短时在最高频率采样，硬件 CPU 电源轨与固件电压表一致：
  domain 0/1/2 对应 `vddcpu1/2/0`。采样后恢复原调速器。
- 三簇保存 +3125 µV 并正常重启后，31 个固件频点全部恰好提高 3125 µV，
  频率列表不变；分别最高频率采样的硬件 CPU 轨与新表吻合。
  随后保存 0 并再次正常重启，31 个频点电压全部恢复基线，当前/下次偏移均为 0，
  无异常启动回退，三个调速器均为 schedutil。
- 最终原厂阈值为 70/85/110°C；5 秒采样中 CPU0 的 cluster-pd 次数
  从 1315 增至 1463，驻留时间从 1496734 增至 3520902 µs。
  WAN up、热点接口和屏幕进程运行、默认启动仍为 OpenWrt。
- 本次未替换内核/模块，只原子部署公共 CPU helper；原始回执保存在
  忽略目录 `out/t512n/cpu-power/`。
- 当前启动日志仍有之前已发现的显示 DMA-BUF/SWIOTLB 导入错误。
  不能将本轮的 CPU/温控验证写成显示驱动已经全部修好，或据此量化续航提升。

完整充放电、长时间续航和所有电压档位稳定性不在本次验证范围内。
