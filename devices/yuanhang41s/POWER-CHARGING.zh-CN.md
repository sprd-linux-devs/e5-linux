# 远航 41S 电源适配与证据

原厂版本及 SoC 见 README。以下针对 P720S11 实机，不把其他型号的 PMIC、
电池表或相机域直接套入。本记录将接口/短时回归与完整充放电分开。

## 关机充电与长按开机

720×1600 充电画面及本机原厂 loader 的冷启动适配已补齐，见
[关机充电修复与验证边界](CHARGER-BOOT-20261020.zh-CN.md)。

## SGM41513 与充电控制

2026-11-01 用户报告确认另一批次为 `0x6b REG0B=0x11`，按本机原厂驱动
识别为BQ25601。已增加按PN及实际地址选择的识别/电流编码，原0x1a样机
路径保留；证据、回归和尚未实测的边界见
[充电芯片批次识别](CHARGER-VARIANTS-20261101.zh-CN.md)。

原厂 DT 使用 `ti,bq2560x_chg`、I2C6 地址 0x6b，但本机 SQC 驱动实际切到
0x1a，日志明确为 SGM41513。适配使用分段充电电流编码、原厂 CV/终止电流
编码及本机 5000 mAh OCV/JEITA 表，不使用 E5/T551M 的电流表。

原厂电脑 SDP 输入限制也是 500 mA；不能以当前连接电脑的读数判定充电器
只有这个能力，也不能强行向未协商的电脑端口请求充电器电流。

实机通过真实 `e5-charge.configure` 暂时启用一个低于当前电量的充电上限：
CM `stop_charge=1`、`externally_control=1`，SGM 状态变为 `Not charging`；
恢复原始配置后，两项回到 0，状态恢复 `Charging`。USB 管理连接保持可用。
这证明限充控制链路，不代替充电器、电流表或完整充电终止测试。

## FGU 启动校准缺口

实际原厂模块 `sc27xx_fuel_gauge.ko` SHA-256：
`eb1fb27109beb1c6d804effeb0f8ed5064934a26b4ddd241c46adcbe62f1e65f`。

反汇编 `sc27xx_fgu_boot_cap_calibration`（0x43ac）：

- 0x4598–0x45c8 读取实时 OCV，转成 µV，并计算与 POCV 的绝对差。
- 0x45c8 的判断为差值小于 300001，即允许相差最多 300000 µV。
- 差值过大或实时读数失败直接退出；之后才考虑校准及 900 秒关机时长条件。
- 保留区的整数百分比和十分之一编码与现有 UMP 驱动一致，不能改成另一套编码。

移植的 FGU 核心缺少实时 OCV 比较，样机 POCV 一直是 3.517 V，实时 OCV
却约 4.2 V。现已在 41S profile 补入原厂检查；实机启动日志明确拒绝了
`stale POCV 3517000, live OCV 4223 mV`。正常校准条件、有效 SOC 保留、
关机保存、充电终止和低电保护没有被取消。

此前错误校准可能已经留下偏低的原始 SOC，界面平滑值与它仍可能不同。
这次不向保留寄存器强写一个“看起来合理”的百分比；不能把防止再次错误
校准等同于已完成历史误差恢复。正常完整充电及休眠校准的恢复效果仍需长测。

后续补上 SGM 硬件 FULL 状态与 CM 满电端点，替换供体的终止判据；原厂
模块及实际 SQC daemon 的取证、实现差异和验证边界见
[电量端点恢复记录](BATTERY-ENDPOINT-20261020.zh-CN.md)。

## USB 角色

本机 UMP9620 CC 路径补上公共 `usb_role_policy` / `usb_role` 接口。
不伪造外设连接、不绕过实际 CC 检测，也不因选了 host 就向电脑反向供电。

实机依次切换 device / auto / host / auto，回读一致；连接电脑时强制 host
状态为 none、USB-HOST=0，恢复 auto 后重新识别电脑并恢复 NCM。错误参数
被拒绝，最后保留自动策略。当时未测试物理 OTG 外设和充电器插拔。

后续用户已确认：普通 OTG 外设可用、向外供电正常。但带供电扩展坞无法
同时充电和使用 OTG；这项与普通 OTG 分开，不标为扩展坞通信已通过。

静态检查确认当前 `devices/m8/dwc3-role.h` 将 host 和 boost 绑定，
`devices/m8/usb-role.py` 的 PHY 路径进入 host 时停止 BC1.2 受电检测。
所以当时的实现没有支持“数据 HOST + 电源 SINK”。原厂配置启用了 TCPM，
模块包包含 `sprd_tcpm.ko`，但本机实采 `pd@e00` 节点为 `status = "disabled"`。
驱动或控制器存在不代表本板已经验证可用的 PD 角色协商。

后续若实现，应按实际协商独立控制数据角色和供电角色：扩展坞供电时停用
本机 boost，维持 host 并保留受电检测；不能在外部 VBUS 存在时直接强开
boost，也不能仅凭设置 host 就声称支持 PD。U30 Air 的 TCPM 实现可作接口
参考，不能直接套用其板级参数。

### 用户授权的手动外部供电模式

后续按用户要求，新增 `host-sink` 实验策略，仅由 41S 的内核准备器接入：

- Type-C CC 选择 SNK，保留真实 sink/外部 VBUS 事件；没有伪造 USB_HOST extcon。
- 独立把 DWC3/PHY 设为数据主机，不调用 SGM41513 的 boost enable。
- 先等待既有 BC1.2 检测完成，再启动主机数据，保留实际检测到的充电类型和
  电流限制；不伪装 DCP/PD，也不在运行中的主机数据链路上反复重做探测。
- 通过 CC、VBUS、充电检测事件调度，未增加后台轮询。外部电源断开时更新
  PHY VBUS valid、退出主机并停止充电；回到普通供电 OTG 前再次核对外部 VBUS。
- 网页“设备管理 → USB 角色”和屏幕“设置 → USB”只有检测到新内核能力时才
  显示“主机＋外部供电（实验）”。不提供开机自动应用，重启恢复自动模式。

实机用电脑提供的 5V 作受电对照：真实控制器为 host，xHCI 两个根集线器已
注册，Type-C 电源角色为 sink、数据角色为 host，电池和 SGM 均为 Charging，
内核明确记录 `role=host boost=0 external=1`。对照后自动恢复 NCM，未改变
Android 槽、NV、网络或充电上限设置。这证明受电/数据主机可同时配置，
不代表已经验证用户扩展坞上的网卡通信。

补齐外部 VBUS 拔出处理的最终内核再次通过同一实机对照。直接读取 SGM
REG01=`0x9a`，OTG boost 位 bit5=0；回到自动模式后，USB 双向各 8 MiB
SHA-256 一致，DNS/IPv4/IPv6 正常，原 Android B 哈希与 237 个模块校验通过。
实际屏幕 API 也列出新选项，中文 UTF-8 与源码一致，最终停留在 auto/device。
回执保存在忽略目录 `out/yuanhang41s/acceptance/host-sink-final-state.json`。

实际 C 回归覆盖源/受电互斥、检测未完成、拔电、已有 boost 退出、VBUS
中途出现、控制器/PHY/升压开关失败及无 xHCI；普通 host 保留原路径。
网页测试覆盖能力过滤、禁用开机保存和恢复原模式。跨机型复用错误的 41S
源码会提前拒绝，避免 M8 等机型暴露未配套的策略。

使用：先给独立供电扩展坞接上充电器，再手动选择该模式并连接扩展坞。
需要扩展坞无需 PD 协商就向上游口提供 5V 且开放数据；如果它要求 PD 的
DR_SWAP/PR_SWAP 才开放接口，单靠此手动策略仍不能完成协商。

后续用户扩展坞日志暴露了 Unknown 检测完成漏通知，已补充事件路径；
Unknown 不会因此变成有效充电器。快速掉百分比也已确认主要是 UI 追赶
失真的保留 SOC，另有普通 OTG 的真实放电；证据及未解决边界见
[扩展坞与 SOC 记录](DOCK-SOC-20261020.zh-CN.md)。

## 省电与未测范围

本机保留原厂调频/温控及公共电量保护；不默认降压、降频、禁用 eMMC 休眠。
早期探测使用的 `clk_ignore_unused` / `pd_ignore_unused` /
`regulator_ignore_unused` 已移除，并在正常启动后重新完成屏幕/网络/限充回归。
不把 E5 的 qogirl6l 相机域兼容项直接加到本机 qogirn6pro。

移除后发现并实机复现了一个时钟驱动缺口：AI bank 的 7 个子 gate 虽然
有 `ai-eb` 父时钟，但没有标记 `SPRD_GATE_NON_AON`。AI 总线正常关闭后，
`clk_summary` 的 `is_enabled` 仍直接访问 0x27000000，触发 SError。
有限 kprobe 记录将最后一次访问定位到 `nic400-busmon-eb`；异常已保存到 pstore。

公共 UMS9620 准备器现给这 7 个 gate 补上现有核心驱动支持的标记，与本 SoC
音频 gate 已用的机制一致；父时钟关闭时返回未启用，不读不可访问的子寄存器。
不常开 AI 总线、不增加轮询，也不修改其他平台时钟。离线编译实际核心函数
验证父门关闭/打开及普通 AON 路径；新内核实机完整读取 597 行时钟摘要，
息屏状态再读取三次，boot_id 不变。AI 父门及子门仍为关闭。

同一台设备移除参数前后均读到 503 个时钟，其中 21 个从硬件启用变为关闭，
包括 AI、调试和未使用接口门。该短时快照证明资源清理生效，不表示已测出
具体待机电流或续航提升，也不表示全部差异均由同一个启动参数引起。

完整放电曲线、充满终止、低电切断、关机充电实体按键/拔线、实际待机电流、
蓝牙实际通话及物理充电器测试都不能用接口读数或离线测试冒充通过。
普通 OTG 已获用户实物确认；实际扩展坞同时充电和网口通信于 2026-10-22
获得用户确认并只读复核，见下节。U 盘及其他扩展坞组合仍未验证。

## 2026-10-22 实际扩展坞网口与充电

用户确认当前通过独立供电扩展坞的网口连接电脑，同时给 41S 充电，要求保留
现有实现。只读检查确认机型为 `yuanhang41s`，运行内核
`6.18.54-yuanhang41s-bringup1`：

- Type-C 数据角色为 `host`、电源角色为 `sink`；未切换模式或重启。
- Realtek `0bda:8153` 网卡使用 `r8152`，`eth0` 加入 `br-lan`，链路为
  1000 Mbps 全双工。USB 枚举是 high-speed，因此千兆协商值不等于实际吞吐。
- 电池与充电芯片均报告 Charging；电池侧电流两次读数为 +502/+582 mA。
  该值不是 USB 输入电流。当前输入限流为 1000 mA、充电设定为 960 mA。
- 间隔五秒，网卡 RX 从 95832 增至 98081 字节，TX 从 60869 增至 64029；
  RX/TX errors 均为 0，RX dropped 保持 3，没有新增。

这是用户实际使用与短时软件状态的共同证据，不代表长期稳定、全部扩展坞、
热拔插或 PD 角色交换都已验证。本次没有修改功能、充电参数或网络配置。
