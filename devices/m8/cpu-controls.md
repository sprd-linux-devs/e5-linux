## 固件接口

M8 / UMS9620 的两个 1 MiB SML 分区相同，SHA256：
`31425dab4aca8450757ac4207de419d06643b7204776fc7e8da5aab1d68814df`。
这是本机只读提取分析的固件，不是沿用 E5 或 F50 的哈希。

`DVFS_INIT (0x8200060b)` 的分发点 `0xb000bed4` 调用 `0xb00058b0`：
bits 8..31 分别为三个 domain 的有符号幅度字节，bit7 为负号，低 7 位为 mV。
`0xb0004dfc` 把偏移保存在 domain 数据中，`0xb000306c` 以
`ceil(mV * 1000 / 3125)` 个 selector 调整电压表；其指令与已验证 F50
固件对应函数一致。`0xb000420c/0xb0004218` 分别作用于 CPU/SRAM 表。

保留一次性 DVFS 初始化、只读模块参数、禁止卸载/重新绑定和异常启动回退。
CPUFreq 模块不在 initramfs 提前加载，而由真实根目录的 S13 CPU 服务加载；
否则提前以零偏移初始化会让保存的电压配置始终无法生效。
公共后端按 SoC 分别核验两个 SML 分区，只有匹配本机固件才接受非零偏移。
每簇范围 −50 至 +25 mV，步进 3.125 mV，保存后重启生效；默认零偏移。
不修改安全固件、原始 NV、DTBO，也不直接写 PMIC 寄存器。
这不是对整个可调范围的稳定性保证。

M8 三簇为 CPU 0–3、4–6、7，不能照搬 E5 的 CPU/SRAM 电源轨对应关系。
尚未核验的 PMIC 轨回读不展示，频率/电压表由固件 PAIR_GET 返回。

## 原厂温控恢复

原厂 `soc-thmzone` 的传感器是 `virtual-thermal`，并非单个物理传感器。
只导入 r5p0 驱动会留下 23 个能读温度的区，但遗漏整个 CPU 温控区。
`sprd_virtual_thermal.c` 沿用 MU300 驱动实现，来源
`kanoqwq/mu300-linux` 提交 `5c8c2f9582beb83301c09d8cb87a60bf26d397de`，
文件 `upstream/modules/mu300_thermal/mu300_thermal.c`，GPL 许可保留。

驱动使用本机 DT 的 `thmzone-cells` 列表，取最高温度，复用原厂 trips 和
cooling-maps。物理传感器未准备好时延迟注册；读失败不伪装成低温。
默认 70°C 提高监测频率、85°C 绑定三个 cpufreq 降频设备、110°C 过热关机。
默认轮询 1 秒，被动状态 100 ms，沿用原厂设置，无额外后台轮询进程。
网页及屏幕使用同一 CPU 后端，可修改被动阈值、保存开机配置、恢复默认。
页面不开放 critical 温度修改。

补齐 `scaling_requested_min_freq/max_freq`，使临时温控限频不被误存为
用户请求上限。实际有效上限仍独立显示。

## 2026-10-12 实机验证

内核 `6.18.54-m8-probe12-g020b970e351e-dirty`，最终启动镜像
`boot-openwrt-persistent3.img`，SHA256：
`813ac2f1aaeefbc787a8ba15508359001abc0f6fe22841f9488d3d6712fa7c74`。

- 恢复 `soc-thmzone`，三个 cpufreq cooling 设备绑定 trip 1。
  临时设 40°C / 41°C 后，三个 cooling state 均为 4，有效上限降为
  936 MHz；保存配置仍保留原请求上限。恢复阈值后全部回到 state 0。
- 限频 1404 MHz、监测起点 69°C 保存后重启，均自动应用。
- 电压验证期间用户自行将三簇设为 −12.5 mV，并明确要求保留。
  重启后参数为 `-12500,-12500,-12500`，三个域各 7 个频率不变，
  全部 21 个固件电压值相对零偏移基线恰好降低 12500 µV。
  再次正常重启后仍为同一偏移，没有累计叠加或误触发异常启动回退；
  默认 OpenWrt 启动保留，屏幕、USB 管理网和蜂窝连接恢复。
- 固定频率采样：CPU0 在 1560 MHz 时 `vddcpu0` 从 753125 降到
  740625 µV；CPU4 在 1536 MHz 时 `vddcpu1` 从 728125 降到
  715625 µV。不能因此把所有 CPU/SRAM 电源轨后缀当成 domain 编号。
- 已登录的 LuCI 页面显示三个电压选择器、两个可写温控阈值；应用、
  刷新回读及临时设置还原通过。1280/390 px 布局无横向溢出或 JS 错误。
  实际屏幕 API 的 policy0/4/7、三张电压表、温控写入和恢复也通过。
- 21 项公共 CPU 后端测试、7 项 M8 刷入保护测试和 CPU 浏览器/屏幕
  导航测试通过。未进行极限降压、长时间高负载稳定性或长期续航测试。

交付保留用户的 −12.5 mV，调速器为 schedutil、原厂频率范围，
温控阈值 70/85/110°C；测试用开机调频/温控配置已清除。
