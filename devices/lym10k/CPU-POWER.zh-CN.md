# LYM-10K：CPU 调频、SMC 调压与温控

> 2026-11-01 现行规则：下列原厂哈希继续作为取证记录及快速白名单；
> 未命中时使用共享只读算法匹配，不再只按版本/签名判定，也不要求两槽镜像相同。
> 本文保留此前适配和实测时的历史检查条件。现行实现及边界见
> [公共调压说明](../../docs/CPU-CONTROL.zh-CN.md)。

## 原厂输入与镜像范围

基准为 `LYM-10K-V32` 的原始 SML A/B；两份文件均为 **157224 字节**，
SHA256 均为 `25447f40532d7dcb2b86b343ae9cfc8fb14f8384011089d68d268f88c31e04c6`。
文件虽不足 1 MiB，但它们是完整签名镜像，不是仅提取了一段 DVFS 代码：

- 头部 magic/version 为 `DHTB` / 1，头部大小 0x200。
- 0x30 的 payload 长度为 0x25f90，payload SHA256 与头部 0x08..0x27 一致：
  `1dd20f4312b235f4d98a6092b73ae51215f5d1b0681b75d857b753136378826f`。
- 0x50 的签名镜像总长为 0x26628，覆盖头部、完整代码/数据和尾部证书。
- payload 在 SML 的加载地址为 0xb0000000；以下 VA 对应文件偏移 `VA - 0xb0000000 + 0x200`。

公共 CPU 后端对 LYM 使用这个**完整签名镜像**的长度和 SHA，不把分区末尾未使用的
填充算进身份；既有其他机型继续使用原来的整分区 SHA 规则。仍要求机型为
`lym10k`、精确 SoC compatible 为 `sprd,ums9621`，并且两槽都识别为同一个已核验镜像。
截断、头部/代码/数据/证书变化、另一槽缺失或未知固件不会被当作支持。
能力缓存升级到 v7，使此前 v6 的“不支持”缓存重新检查。

## SMC 调用链

已只读核对本机原厂二进制：

| 环节 | 原厂 VA 与证据 |
| --- | --- |
| SMC `0x8200060b` | 0xb000d358 的 DVFS 分发；0xb0013c50 的 13 项字节跳转表，index 11 为 0x28 |
| DVFS_INIT 分支 | 0xb000d448 调用 0xb0007300；保存传入 flag 到 w20 |
| flag 解码 | 0xb000753c 恢复 flag，0xb0007540 调用 0xb0006248 |
| 三个域 | 分别取 bits 8..15、16..23、24..31，bit7 表示负，低七位为 mV；幅度超过 100 不采纳 |
| 状态位置 | 0xb0028068 + 0x1c/0x4c/0x7c；不更改低字节原有标志 |
| CPU/SRAM 成对调整 | domain 0：0xb0005628/0xb0005634；domain 1：0xb00051f0/0xb00051fc；domain 2：0xb0004d44/0xb0004d50 |
| selector 算法 | 0xb0004068，步数为 `(mV*1000 + 3124)/3125`，按符号调整表项；每张表 1..16 项 |

对应 selector 函数与已核验 T512N 的同段代码逐字节相同；本次还独立核对了 LYM
自己的分发、解码、三域 CPU/SRAM 调用及温度表去重分支，未仅凭相似机型开放。

## 已接入的功能

- `CONFIG_ARM_SPRD_CPUFREQ_V2=m`、`CONFIG_SPRD_SIP_SVC=y` 已在编译的 LYM 内核中。
  驱动保留原厂 binning、频率/电压表、三个频率域和温度表，不写一张别的机型的 OPP 表。
- 调频、调速器、核心开关、频率/电压表读取、被动温控设置均使用公共实现。
- 网页和实体屏幕共用 `cpu-control`：三簇分别设置电压偏移，范围 −50 至 +25 mV，
  步进 3.125 mV，默认 0；保存为下次启动设置。已有保存/开机应用和恢复默认入口复用。
- S13 加载模块时将三域参数传给原厂 DVFS_INIT，只初始化一次。电压参数不在运行中
  重复执行；不通过写 PMIC、SML、NV 或 DTBO 来调压。
- UI 分开显示当前偏移和下次偏移，保存后提示需要重启；不会把保存值伪装成实际电压。
- 充电关机模式使用默认电压，保留用户保存值；异常关机恢复原厂电压的既有行为保留。
- 频率选项来自原厂固件支持列表；没有为本机凭空增加超频频点或开放逐点任意电压。

## 验证与边界

`verify-sml.py --sml <本机原始 sml_a.bin>`：

1. 校验完整签名镜像、payload SHA 和 SMC 跳转/配对调用位置。
2. 用真实 SML 镜像构造临时双槽和模拟 sysfs，走公共设置、三域持久化、模拟启动加载参数
   与正常关闭清除标记流程，确认 SML 字节不变。
3. 在已有 ARM64 Docker 仿真环境执行**原厂实际机器码**的两个纯内存函数：
   flag 解码、selector 调整；793 组域/符号/幅度组合及 CPU/SRAM 成对修改检查通过。
   测试没有执行 SMC、MMIO，也没有连接实机。

公共 CPU 后端 29 项回归通过，新增覆盖：完整镜像与不同尾部填充、头部/代码/证书损坏、
缺槽、错误机型/SoC、超长/截断镜像、旧缓存刷新；其他机型的整分区规则回归通过。
Chromium 网页控件和屏幕嵌套设置测试通过。

这些验证确认源码接入和原厂 ABI 的离线行为；**仍未实测本机 SMC、实际电源轨与稳定性**。
后续接入 LYM 时应先读取零偏移基线，再短时验证小偏移、重启生效及恢复默认。
